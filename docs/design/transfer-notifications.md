# Сообщения к переводу и уведомления о зачислениях

Диалог перевода: получатель → сумма → необязательное сообщение (до 1000 символов)
или кнопка «Без сообщения» → подтверждение с полным текстом → запись перевода.
Сообщение нормализуется trim; пустое сообщение сохраняет прежний fingerprint операции.
Непустое сообщение входит в fingerprint, изменение текста с тем же action_key запрещено.

Таблица money_notifications создаётся аддитивно при init/start. Одна запись на блок,
вставка атомарна с блоком и processed_actions. Повтор подтверждения не создаёт новое
уведомление. Старые блоки, хеши и receipts не меняются; старые переводы не рассылаются.
Текст сообщения хранится как метаданные, вне хеша блока. При поиске по ID текст
доступен только настроенному администратору по Telegram ID в личном чате с ботом.
Для остальных пользователей и в группах метаданные сообщения не читаются и не выводятся.
Личное уведомление получателю по-прежнему содержит адресованное ему сообщение.

При откате к старому коду таблицу money_notifications нужно сохранить: старый код
игнорирует сообщения и очередь, повторный upgrade возобновляет доставку. Старый API
без сообщения не может повторить receipt перевода с непустым текстом: возникает
конфликт идемпотентности, повторного изменения баланса нет.

Получатели — зарегистрированные Telegram ID. Уведомляются переводы игроков,
начисления администратора, а также новые CLI-зачисления на точный аккаунт @username
после обновления схемы. Стартовые $100 уже сообщаются ответом на /start.
Администратор обозначается отдельно от system; если зарегистрирован, показывается username.

Доставка запускается post_init и останавливается post_stop/post_shutdown. Отправка
отделена от диалога: ошибка ответа отправителю не теряет уведомление получателя и
ошибка уведомления не отменяет зачисление. Записи захватываются BEGIN IMMEDIATE с
арендой 300 с и номером попытки; устаревшая попытка не может изменить новую.
Успешные/постоянно отклонённые сообщения не повторяются. Сетевые ошибки повторяются
с задержкой 5–300 с, RetryAfter учитывается, Forbidden/BadRequest закрывают запись.
Незавершённая отправка после аварии доступна по истечении аренды.

Доставка имеет семантику at-least-once: при потере ответа Telegram или аварии между
send_message и записью sent возможно повторное уведомление с тем же ID транзакции.
Баланс повторно не изменяется. Формат plain text; предпросмотр ссылок отключён.
Тестирование только с временными БД и заглушками Telegram, без рассылки пользователям.
