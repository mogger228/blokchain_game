# Design: простая Telegram-игра на учебном блокчейне

Статус: подтверждён пользователем 2026-10-06

Дата: 2026-10-06

## Цель

Добавить к существующему мини-проекту простого Telegram-бота, через которого зарегистрированные игроки могут переводить игровую валюту, смотреть баланс и цепочку, проверять целостность и находить транзакцию по ID. Один Telegram ID получает защищённую админ-панель для просмотра игроков и выпуска игровой валюты.

Это учебная игра. Монеты не имеют реальной стоимости, криптографических кошельков, приватных ключей и связи с настоящими блокчейн-сетями нет.

## Границы первой версии

Входит:

- один бот и одна общая SQLite-цепочка для всех зарегистрированных игроков;
- автоматическая регистрация по Telegram username и стартовое начисление `$100` ровно один раз;
- привязка игрового отправителя к Telegram ID, без ручного ввода чужого имени;
- автоматическая безопасная инициализация таблиц и генезис-блока при запуске;
- создание перевода зарегистрированному username;
- просмотр игроком своего баланса и администратором балансов всех игроков;
- поиск блока по целочисленному ID;
- вывод всей цепочки несколькими Telegram-сообщениями, если она не помещается в одно;
- проверка целостности цепочки;
- отдельная админ-панель для Telegram ID из конфигурации;
- постраничный список всех игроков и их балансов;
- административное начисление произвольной положительной суммы выбранному игроку;
- сохранение существующего CLI поверх той же прикладной логики;
- long polling, запуск одним локальным процессом.

Не входит:

- реальные деньги, комиссии, майнинг, proof-of-work, ключи или подписи;
- пароли, приватные ключи и передача игрового аккаунта другому Telegram ID;
- несколько администраторов, роли, webhook и публичный сервер;
- удаление или редактирование блоков;
- изменение формата таблицы `blocks` или пересчёт хешей существующих блоков.

## Пользовательский интерфейс

При первом `/start` бот регистрирует пользователя под его текущим Telegram username и атомарно добавляет стартовую транзакцию `system -> @username` на `$100`. Если username не задан, бот объясняет, как установить его в Telegram, и не создаёт частичную регистрацию.

Игровой username фиксируется при первой регистрации. Последующая смена username в Telegram не переносит баланс и не переименовывает старые блоки: бот продолжает показывать зарегистрированное игровое имя. Один Telegram ID может иметь только одну регистрацию, а один нормализованный username — принадлежать только одному Telegram ID.

После регистрации команда `/start` показывает краткое объяснение и постоянное главное меню с inline-кнопками:

- `💸 Создать транзакцию`
- `💰 Узнать баланс`
- `🔎 Найти по ID`
- `⛓ Показать цепочку`
- `✅ Проверить цепочку`
- `ℹ️ Правила`

Для настроенного администратора дополнительно показывается кнопка `🛠 Админ-панель`. Проверка прав выполняется по числовому Telegram ID при каждом административном callback, а не только при построении меню.

### Создание транзакции

Диалог идёт последовательно:

1. Отправителем автоматически становится зарегистрированный игровой username текущего Telegram ID.
2. Бот просит username получателя и принимает написание с `@` или без него.
3. Получатель должен быть зарегистрированным игроком; имя нормализуется без учёта регистра.
4. Бот просит положительную сумму.
5. Бот показывает сводку и кнопки `Подтвердить` / `Отмена`.
6. После подтверждения сервис атомарно проверяет баланс и добавляет блок.
7. Ответ содержит ID, перевод, хеш и кнопку возврата в меню.

Обычный игрок не может указать `system`, чужое имя или Telegram ID в качестве отправителя. Он может отправить не больше текущего баланса.

### Баланс

Кнопка главного меню сразу показывает баланс текущего зарегистрированного игрока. Отдельный запрос чужого баланса игроку не требуется; все балансы доступны администратору в списке игроков.

### Админ-панель

Админ-панель содержит кнопки:

- `👥 Пользователи и балансы`;
- `➕ Начислить`;
- `⬅️ Главное меню`.

Список выводится страницами по 10 игроков. Для каждой строки показываются зарегистрированный `@username` и баланс, рассчитанный по цепочке. Кнопки `Назад` / `Вперёд` переключают страницы.

Сценарий начисления:

1. Администратор нажимает `Начислить`.
2. Бот показывает постраничный список игроков-кнопок и также принимает точный зарегистрированный username.
3. После выбора получателя бот предлагает суммы `$10`, `$50`, `$100` и кнопку `Другая сумма`.
4. Для другой суммы бот принимает любое положительное число.
5. Перед записью показываются получатель, сумма и кнопки `Подтвердить` / `Отмена`.
6. Подтверждение создаёт обычный блок `system -> @username`; ответ содержит ID транзакции.

Таким образом, начисление выполняется **из админ-панели**, но не списывается с личного игрового баланса администратора. `system` остаётся техническим эмитентом, а доступ к его использованию через Telegram имеет только `TELEGRAM_ADMIN_ID`.

### Поиск по ID

Бот принимает неотрицательное целое число. Для найденного блока показывает ID, время, отправителя, получателя, сумму, hash и previous hash. ID `0` отображается как генезис-блок. Для отсутствующего ID выдаётся понятное сообщение.

### Цепочка и валидация

Цепочка форматируется компактно и разбивается на сообщения короче лимита Telegram. Проверка целостности возвращает либо `Цепочка валидна`, либо ID первого повреждённого блока.

Команда `/cancel` отменяет любой незавершённый диалог и возвращает главное меню. Бот предназначен для личных чатов; в группе он предлагает открыть личный чат.

## Архитектура

```text
Telegram update / CLI command
            |
            v
  bot.py / main.py       интерфейсы и проверка Telegram-контекста
            |
            v
       service.py        правила сценариев и ошибки предметной области
        /       \
       v         v
blockchain.py  storage.py
  блоки/хеши    SQLite и атомарная запись
```

### `blockchain.py`

Остаётся чистой предметной логикой: блок, построение следующего блока, баланс и проверка цепочки. Формат хеша существующих блоков не меняется.

### `storage.py`

- Путь к БД задаётся через `BLOCKCHAIN_DB_PATH`; по умолчанию используется `chain.db` рядом с файлами проекта, а не текущий каталог оболочки.
- `init_db()` становится идемпотентным: создаёт таблицы при отсутствии и добавляет генезис только когда таблица `blocks` пуста.
- Добавляется таблица `players`: `telegram_id` как первичный ключ, нормализованный `username` как уникальное поле, время регистрации и ID стартовой транзакции.
- Добавляется таблица `processed_actions` с уникальным ключом подтверждения и ID созданного блока, чтобы повторная доставка одного Telegram callback не создавала повторный перевод.
- Регистрация игрока и блок стартового начисления записываются в одной SQLite-транзакции. Повторный `/start` не создаёт ни второго игрока, ни второго начисления.
- Добавляется `get_block_by_index(id)`.
- Добавление транзакции выполняется внутри `BEGIN IMMEDIATE`: чтение цепочки, проверка баланса, вычисление следующего индекса и `INSERT` образуют одну критическую секцию.
- Существующая схема и данные сохраняются без миграции.

### `service.py`

Единый синхронный API для CLI и Telegram:

- `initialize()`;
- `register_player(telegram_id, username)`;
- `create_player_transaction(telegram_id, recipient_username, amount, action_key)`;
- `get_player_balance(telegram_id)`;
- `list_players_with_balances(page)`;
- `create_admin_grant(admin_telegram_id, recipient_username, amount, action_key)`;
- `get_transaction(transaction_id)`;
- `get_chain()`;
- `check_chain()`.

Сервис нормализует username: удаляет один начальный `@`, приводит к нижнему регистру и проверяет формат Telegram username. Для записи в цепочке используется каноническая форма `@username`. Сервис отклоняет незарегистрированного получателя, неположительную или нечисловую сумму и перевод самому себе. Он возвращает данные или типизированные ошибки; тексты для пользователя остаются в интерфейсных слоях.

### `bot.py`

- Использует `python-telegram-bot` 22.x, `ApplicationBuilder`, асинхронные callback-функции и `ConversationHandler`.
- Токен читается только из `TELEGRAM_BOT_TOKEN`.
- Числовой ID единственного администратора читается из `TELEGRAM_ADMIN_ID`; отсутствие или неверный формат останавливают запуск с понятной ошибкой.
- Доступ к админ-панели и каждый административный callback повторно проверяют `update.effective_user.id`.
- Stateful-диалоги обрабатываются последовательно (`concurrent_updates=False`).
- Блокирующие короткие вызовы SQLite остаются синхронными: для масштаба одного учебного бота это проще и предсказуемее.
- Секреты и пользовательский ввод не пишутся в логи.

## Согласованность и ошибки

- Каждый подтверждённый перевод либо целиком записан одним новым блоком, либо не записан вовсе.
- Регистрация и стартовые `$100` также фиксируются атомарно и идемпотентно.
- При одновременных подтверждениях SQLite сериализует запись; баланс проверяется уже внутри транзакции.
- Перед добавлением нового блока сервис проверяет целостность текущей цепочки. В повреждённую цепочку новые блоки не добавляются.
- Ошибки ввода не завершают диалог: бот объясняет допустимый формат и повторяет текущий шаг.
- Ошибка Telegram API не откатывает уже зафиксированный блок; повторное нажатие одной и той же кнопки подтверждения в рамках сообщения не должно создавать второй блок.
- Повторное подтверждение админского начисления также не создаёт второй блок.
- Подделанный callback или команда от другого Telegram ID не может вызвать выпуск монет.
- Суммы остаются `float`/SQLite `REAL`, чтобы не менять схему и хеши существующей цепочки; вывод пользователю использует компактное форматирование без лишних нулей.

## Совместимость CLI

Команды остаются доступными:

```text
python main.py init
python main.py send --from @alice --to @bob --amount 100
python main.py balance --user @alice
python main.py chain
python main.py validate
python main.py transaction --id 1
```

`main.py` остаётся доверенным локальным учебным/диагностическим интерфейсом и тонким адаптером к общим операциям цепочки. Регистрация игроков и административные права относятся к Telegram-интерфейсу; локальный доступ к файлу БД считается доступом владельца проекта, а не удалённого игрока.

## Конфигурация и документация

- `requirements.txt` фиксирует совместимую ветку `python-telegram-bot`.
- `.env.example` содержит `TELEGRAM_BOT_TOKEN` и `TELEGRAM_ADMIN_ID` без настоящих значений.
- `.gitignore` исключает `.env`, виртуальное окружение, кэш Python и локальные БД.
- `README.md` содержит создание бота через BotFather, настройку токена, установку, запуск CLI/бота, игровой сценарий и quick start.

## Проверка результата

Автоматические тесты работают на временной SQLite-базе и покрывают:

- идемпотентную инициализацию и единственный генезис;
- регистрацию игрока и единственное стартовое начисление `$100` при повторных `/start`;
- запрет регистрации без username, дублирования Telegram ID и дублирования username без учёта регистра;
- выпуск монет от `system` через администратора и обычный перевод между игроками;
- отказ при недостаточном балансе, неположительной сумме, пустом имени и переводе самому себе;
- запрет админ-панели и начисления для любого другого Telegram ID;
- список игроков, пагинацию и корректно рассчитанные балансы;
- сохранение корректной цепочки и выявление повреждения;
- поиск существующего и отсутствующего ID;
- отсутствие двойной записи при повторном подтверждении;
- форматирование длинной цепочки в допустимые Telegram-сообщения;
- основные переходы диалогов бота без обращения к реальному Telegram.

Финальный gate задачи:

1. Все автоматические тесты проходят.
2. Три независимых ревьюера `review-deep` дают `PASS` после фазы планирования и повторно после исправлений, если были замечания.
3. На чистом окружении буквально выполняются команды раздела `Quick start` из `README.md`.
4. Smoke-сценарий создаёт тестовую БД, регистрирует двух игроков со стартовыми `$100`, выполняет перевод, делает админское начисление, проверяет список и балансы, находит переводы по ID и подтверждает валидность цепочки.

До прохождения этого gate реализация не считается готовой к передаче.

## Принятые допущения

- Все игроки видят одну общую цепочку.
- Игровое имя берётся из Telegram username при первой регистрации, нормализуется и затем остаётся неизменным.
- Стартовые `$100` — отдельная транзакция `system -> @username`, а не скрытое поле в таблице игроков.
- `system` доступен через Telegram только настроенному администратору; это учебный эмитент, а не реальный финансовый счёт.
- Администратор определяется только числовым Telegram ID, потому что username может измениться.
- Существующий `chain.db` сохраняется и используется по умолчанию.
