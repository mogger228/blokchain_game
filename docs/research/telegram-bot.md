# Research: Telegram-интерфейс для учебного блокчейна

Дата: 2026-10-06

## Текущее состояние

- `blockchain.py:11-54` содержит модель `Block`. Хеш блока — SHA-256 от индекса, времени, отправителя, получателя, суммы и хеша предыдущего блока.
- `blockchain.py:57-89` создаёт генезис-блок и следующий блок цепочки.
- `blockchain.py:92-109` вычисляет баланс имени как сумму входящих переводов минус сумму исходящих.
- `blockchain.py:112-139` проверяет сохранённые хеши и связи `previous_hash` между соседними блоками.
- `storage.py:12-135` хранит блоки в локальном SQLite-файле `chain.db`. Таблица `blocks` использует номер блока как первичный ключ.
- `main.py:17-110` реализует операции `init`, `send`, `chain`, `balance`, `validate`.
- `main.py:35-46` разрешает имени `system` выпускать игровую валюту без ограничения и запрещает остальным отправителям превышать рассчитанный баланс.

## Имеющиеся пользовательские сценарии

1. Инициализировать базу и генезис-блок.
2. Создать перевод: отправитель, получатель, сумма.
3. Узнать баланс указанного имени.
4. Вывести всю цепочку.
5. Проверить целостность цепочки.

## Чего сейчас нет

- Нет Telegram-интерфейса и зависимости для Telegram Bot API.
- Нет поиска одного блока/транзакции по ID.
- Нет общего прикладного слоя: проверки и создание перевода находятся непосредственно в CLI-обработчике `cmd_send`.
- Нет проверки положительности суммы и непустых имён.
- Получение последнего блока и его сохранение выполняются раздельно; единая атомарная операция добавления блока отсутствует.
- Нет тестов, `README.md`, списка зависимостей и примера переменных окружения.
- Путь к `chain.db` зависит от текущего рабочего каталога процесса.
- В доступной среде команда `python` отсутствует; Windows launcher `py` также не находит установленный Python. Фактический quick start пока выполнить невозможно.

## Ограничения существующих данных

- Схема SQLite уже достаточна для поиска по ID: поле `index` является `PRIMARY KEY`; миграция для этой функции не требуется.
- Сумма хранится как `REAL`, а модель приводит её к `float`. Изменение типа потребовало бы миграции и изменило бы вычисление хешей существующих блоков.
- ID пользовательской транзакции естественно совпадает с `Block.index`; ID `0` принадлежит генезис-блоку.

## Факты об окружении

- Репозиторий не имеет коммитов; все текущие файлы не отслеживаются Git.
- Существующий `chain.db` должен считаться пользовательскими данными и не должен удаляться или пересоздаваться реализацией.
- Официальная актуальная документация `python-telegram-bot` использует асинхронные обработчики и `ApplicationBuilder`. Для `ConversationHandler` обновления должны обрабатываться последовательно.

## Уточнённые требования пользователя

- Игрок автоматически регистрируется по своему Telegram username.
- Каждый новый игрок один раз получает стартовый баланс `$100`.
- Ручной ввод отправителя игроком больше не нужен: отправитель определяется по регистрации.
- Один Telegram-пользователь, заданный числовым ID, имеет отдельную админ-панель.
- В админ-панели нужен список всех зарегистрированных игроков и их текущих балансов.
- Администратор может выбрать игрока и начислить ему произвольную сумму.
- Административное начисление является выпуском игровой валюты, а не переводом из ограниченного стартового баланса администратора.
